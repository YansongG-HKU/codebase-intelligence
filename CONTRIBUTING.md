# Contributing

Thanks for contributing to Codebase Intelligence.

## Development expectations
- Discuss substantial architectural changes in an issue before implementation.
- Keep pull requests focused and explain the user-visible behavior.
- Add or update tests for every behavior change.
- Document parser coverage, limitations, and fallback behavior.
- Do not include private code, secrets, proprietary datasets, or customer information.

## Pull request checklist
- [ ] Scope and motivation are clear.
- [ ] Tests cover the change and pass locally.
- [ ] Public interfaces and documentation are updated.
- [ ] Parser-derived facts are distinguished from heuristics.
- [ ] Security and privacy implications are considered.
- [ ] No unrelated formatting or generated files are included.

## Design discussions
For changes to the canonical code model, graph semantics, ranking, persistence, or context selection, include examples and explain compatibility implications.
